# PageTwins: one-defect landing page pairs

PageTwins tests whether a model notices when a landing page breaks. Each of 10
original landing pages has 10 "twins" that are identical except for exactly one
labeled defect, plus two control twins: one identical copy and one with a
harmless change.

- 10 base pages (4 layouts: split hero, centered hero, product page, mobile app page)
- 100 defect pairs, 10 per category
- 20 control pairs: 10 identical, 10 harmless (accent hue shift, section reorder, or paraphrased copy)
- 120 pages in total, each as HTML, a full-page screenshot, a first-screen screenshot, and a text view

All brands, products, people, quotes and prices are fictional and were written
for this dataset. No page was copied or scraped from a real website. The hero
illustrations are original SVG drawings generated by code.

## Defect categories

| Category | What changed in the twin | Visible in the text view |
|---|---|---|
| missing_cta | Every sign-up, buy or download button removed | yes |
| hidden_price | Paid prices replaced with "Contact us" or similar | yes |
| contradiction | One claim changed so two parts of the page conflict | yes |
| vague_headline | Headline replaced with one that does not say what the product is | yes |
| typos | Three misspelled words in prominent text | yes |
| placeholder_text | "Lorem ipsum" or a `{{template_variable}}` left in visible copy | yes |
| blocking_popup | A signup modal covers the hero when the page opens | yes |
| low_contrast | Headline color blended toward the background (contrast ratio about 1.25:1) | no |
| broken_image | Hero image points to a missing file and shows the broken-image state | no |
| cut_off_text | Headline box clipped so only part of the first line shows | no |

The last three are visual by construction: their text view is byte-identical to
the clean page, which makes them a built-in check on text-only graders.

## Files

- `pages.csv`: one row per page (`page_id`, `base_id`, `brand`, `template`, `role` = clean / twin / variant, `category`, file paths, screenshot size).
- `pairs.csv`: one row per pair (`pair_id`, `kind` = defect / control, `category`, `clean_page_id`, `other_page_id`, `text_visible`, `text_identical`, `description`, `verified`, `verification`, `pixel_diff_box`, `pixel_diff_area`).
- `categories.json`: the label definitions shown to models.
- `checks.json`: automated DOM measurements per page (primary button count, headline contrast and clipping, image loaded, popup visible, placeholder text, dollar amounts).
- `pages/{page_id}/`: `index.html`, `hero.svg` (absent on purpose for broken_image twins), `screenshot.png` (1280 px wide, full page), `first_screen.png` (1280 x 800), `page.txt` (visible text with element roles).

## How the labels were verified

Every twin was rendered in headless Chromium and measured. A twin is kept only
if the measurement for its category changed as intended (for example, primary
button count drops to zero, headline contrast falls below 1.5:1, the hero image
fails to load) and every other measurement stayed the same as on the clean
page. All 100 defect twins and 20 controls pass these checks
(`verified` column).

Page ids are hashes, so file names do not reveal the label.

## Intended use

Evaluation only. There is no training split. The companion Kaggle benchmark
runs two formats on every model, each with screenshots or with the text view:

- **Pairs**: both versions are shown, in both orders; the model picks the one to ship and names the defect.
- **Solo**: one page at a time; the model lists problems from the fixed label list and gives a 1 to 10 launch-readiness score.

## Limitations

- Synthetic pages with one defect each; real pages have many overlapping issues.
- 10 bases is a small number of designs, so per-category results carry 10 samples each.
- English only, desktop width only.
- Some defects (a contradiction, a vague headline) involve judgment. The pair format reduces this, because the clean twin is the reference.
